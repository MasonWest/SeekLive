# 时光轴 · SeekLive（正式版 Demo）

> 一个可以真正跑起来、手机端体验友好的本地照片时间轴。
>   
> 由「企微图片时间轴 v6」演进而来，并合并了 Live Photo（实况照片）播放能力。

---

## 一、30 秒上手

1. 双击 **`一键启动.bat`**
2. 浏览器自动打开 `http://127.0.0.1:9000/`
3. 手机连同一个 WiFi，用控制台里打印的 **局域网地址** 打开即可

> 首次运行如果提示"已生成配置文件"，说明 `libraries.json` 刚被创建，
>   
> 把里面的 `root` 改成你的照片目录，再双击一次即可。

> **没配管理口令 = 完全公开**：任何人打开这个地址都能直接看照片。
>   
> **配了管理口令 = 默认拒绝**：首页只给一个"壳"，必须**输入口令**或者**点分享链接**
>   
> 才能看到照片 —— 而且**本机 `127.0.0.1` 与局域网走完全相同的规则**，没有后门。
>   
> 详见下方「五、访问控制与免登录分享」。

停止：双击 **`一键结束.bat`**（或在黑窗口按 Ctrl+C）。

## 三、配置图库：一个根目录就够了

编辑同目录下的 `libraries.json`：

```json
{
  "scan": { "ignoreHidden": true, "recheckSeconds": 300, "autoRescan": true },
  "trash": { "retentionDays": 30, "purgeIntervalSeconds": 1800, "autoPurge": true },
  "libraries": [
    { "id": "photos", "name": "我的照片",
      "root": "D:/Photos/我的照片" },
    { "id": "live",   "name": "Live Photo", "root": "D:/Photos/LivePhoto",
      "deletion_enabled": true },
    { "id": "videos", "name": "培训视频",   "root": "D:/Videos/培训视频",
      "deletion_enabled": true }
  ]
}
```

> 完整可复制的模板见 **`libraries.example.json`**（含每个字段的说明）；
>   
> 也可以直接运行 `python server.py --init` 让程序生成一份。
>   
> `libraries.json` 含本机路径，**已被 `.gitignore` 忽略**，不会进版本库。

**另外几个可选字段（不写就是最保守的行为）**

| 字段                           | 缺省      | 作用                                   |
| ---------------------------- | ------- | ------------------------------------ |
| `readonly: true`             | `false` | 该图库**永不**允许删除/恢复（不放心的库建议永远保持 `true`） |
| `deletion_enabled: true`     | `false` | 允许把该图库的照片**移入回收站**（不是永久删除）           |
| `trash.retentionDays`        | `30`    | 回收站保留天数，到期才允许永久删除                    |
| `trash.purgeIntervalSeconds` | `1800`  | 后台到期检查间隔（秒）；`0` = 只在启动时检查一次          |

> `libraries.json` **只管"哪个图库允许删"**，不存管理口令。
>   
> 管理口令是**独立**的（命令行 `--admin-token`，或同目录的 `admin.json`，模板见 `admin.example.json`），
>   
> 且**只影响删除/恢复/永久删除**——浏览照片、视频、时间轴**永远不需要口令**。
>   
> 详见 **`管理认证_独立化方案.md`**。

**目录语义（重要）**：一条 `library = 一个 root 目录`，程序会**递归**扫描它下面的
  
**全部**子目录。你**不需要**手工按「年 / 月 / 事件」去拆分子目录 —— 直接指向
  
你真正的照片总目录（例如 `E:/照片`）即可，它自己会走进去。

- 想加图库就往数组里追加一条，`id` 唯一即可；顶部会自动多出一个胶囊按钮。
- `root` 支持正斜杠 `/` 或反斜杠 `\`。
- 目录不存在 / 临时掉线时会**保留已有索引**并标记「离线」，不会当成空图库清空。
- 每个图库独立建索引、独立缓存（缓存键含 `lib_id`），**不同目录下的同名文件互不干扰**。
- 图库目录**默认只读**：不写 `deletion_enabled` 时，程序不会修改、移动或删除其中任何文件。
    
  （显式打开后，删除也**只是移动**到 `data/trash/`，30 天内可完整恢复）

自动跳过：隐藏目录（`.` 开头）、系统目录（`$RECYCLE.BIN` / `.Trash` / `@eaDir` /
  
`__MACOSX` / `node_modules` / `cache` / `data` / `logs` …）、以及**符号链接 / 目录联接
  
（junction）**——避免递归绕圈。可在 `scan.ignore` 里追加自定义排除项。

程序自身的产物都放在独立数据目录，**不会写进你的照片目录**：

| 路径              | 内容                      | 能否删                     |
| --------------- | ----------------------- | ----------------------- |
| `data/index.db` | 持久化索引（SQLite）           | 可删，下次启动重建               |
| `cache/`        | 缩略图 / 大图 / 转码产物         | 可删，按需重生成                |
| `logs/`         | 运行日志                    | 可删                      |
| `data/trash/`   | 回收站文件区（**在所有图库扫描范围之外**） | 30 天内请勿手动删，恢复用          |
| `data/trash.db` | 回收站账本（批次 / 条目 / 审计）     | 与 `data/trash/` 配套，勿单独删 |

## 四、启动参数

```bat
python server.py                 :: 用 libraries.json 里的图库，仅本机
python server.py --lan           :: 允许局域网访问（手机用）
python server.py --port 9000     :: 指定端口（默认 9000 起自动找空闲端口）
python server.py --admin-token 你的口令  :: 开启访问保护 + 管理授权（浏览也需口令或分享链接）
python server.py --token 你的口令    :: --admin-token 的兼容别名（语义完全相同）
python server.py --no-recheck    :: 关闭后台每 300 秒的自动核对
python server.py --stop          :: 停止后台服务
python server.py --init          :: 只生成 libraries.json 后退出
python server.py --rebuild-index :: 丢弃索引重建
```

> **是否要登录，完全取决于你有没有配管理口令**（这一点在 v1.1 有变化，见「五」）：
>
> **没配口令** → 服务端无法认证任何人，"访问保护"自动不生效：
>   
> 浏览全程免登录（与旧版行为一致），删除 / 恢复等管理操作整体关闭（403）。
>
> **配了口令** → **默认拒绝**：除首页外壳、`/api/session`、分享落地页 `/s/<token>` 外，
>   
> 所有浏览 API 与图片请求一律要求身份（管理员或分享访客），**本机与局域网一视同仁**。
>
> 授权方式（两种情况都一样）：
>
> - **管理员**：首次访问会看到"输入管理口令"入口，输一次即可；此后在**当前浏览器会话**内
>   有效（默认 12 小时；关浏览器即失效）。
> - **分享访客**：打开分享人给的 `/s/<token>` 链接，校验通过后自动种一个只读 Cookie，
>   无需口令、也**只能看到那条分享里被授权的照片**。
>
> 口令**不进 URL、不进 localStorage/sessionStorage**，服务端只下发 HttpOnly 会话 Cookie。

**`admin.json`（可选，独立于 `libraries.json`）**

```json
{
  "adminToken": "你的口令",
  "sessionHours": 12,
  "sessionCookieMaxAge": 0,
  "publicUrl": "https://photos.example.com"
}
```

> 直接复制 **`admin.example.json`** 改名为 `admin.json` 即可。
>   
> **`admin.json` 已被 `.gitignore` 忽略**，不要把口令提交到任何仓库。
>   
> 建议用足够长的随机口令 —— 配了口令之后，**整站（含浏览）都靠它把门**，
>   
> 口令也是唯一能管理删除与分享的操作凭证。

| 字段                    | 缺省   | 作用                                    |
| --------------------- | ---- | ------------------------------------- |
| `adminToken`          | 空    | 管理口令。不写 = 删除功能整体关闭（浏览照常）              |
| `sessionHours`        | `12` | 授权有效期（小时），到期需重新输入                     |
| `sessionCookieMaxAge` | `0`  | `0` = 会话 Cookie（关浏览器失效）；`>0` = 记住 N 秒 |
| `publicUrl`           | 空    | 对外访问地址（如 `https://photos.example.com`）。生成分享链接时用它**替换** `http://127.0.0.1:9000`，复制出去就能直接发给别人。不写协议自动补 `https://`；留空 = 用打开页面时的地址 |

> 启动参数优先级高于 `admin.json`；`libraries.json` **不存口令**，只管每库的
>   
> `deletion_enabled` / `readonly`。

## 五、访问控制与免登录分享

> "默认拒绝"是 v1.1 的核心变化：**先收紧入口，再谈分享**。
>   
> 设计与逐条验收口径见 **`访问控制与分享_设计方案.md`**（定稿 v2）。

### 5.1 三种身份（唯一权威来源 = 服务端）

| 身份 | 凭证 | 能做什么 |
| --- | --- | --- |
| **admin** | `sl_admin` 会话 Cookie（口令换来的） | 全部图库 + 全部管理能力（删除 / 回收站 / 索引 / 分享管理） |
| **share** | `sl_share` Cookie（分享链接换来的） | **只读**，且**仅限该分享被授权的照片**；管理入口全部隐藏且被服务端拒绝 |
| **anon** | 无 | 只有首页外壳（HTML/CSS/JS）与身份接口；拿不到任何相册数据 |

- 前端**只依据** `GET /api/session` 判断身份。URL 上的 `?share=1` **只是界面提示**，
  **绝不是授权凭证** —— 是否放行一律由服务端重新判定。
- **管理员 > 分享访客 > 匿名**；同时带两种 Cookie 时以 admin 为准。
- **本机 `127.0.0.1` 与局域网走完全相同的规则**：`:9000` 端口没有"本机免登录"后门。

### 5.2 默认拒绝：白名单之外一律要身份

配了口令时，只有这些东西可以匿名访问：

```
/、/index.html、/app.css、/app.js、/favicon.svg、/manifest.webmanifest   ← 静态外壳
/api/session        ← 统一身份接口（只回身份，不含任何相册数据）
/api/admin/status   ← 兼容保留
/s/<token>          ← 分享落地页，凭 URL 里的令牌自校验
```

其余全部走统一守卫，并按语义返回：**401 = 未登录；403 = 有身份但没这个资源的权限；
404 = 分享不存在或已撤销**。

> `do_HEAD` 直接复用 `do_GET` → HEAD 与 GET 受**完全相同**的约束，且守卫只判定不执行业务逻辑，
> 不会产生副作用。
>
> 关闭保护：在 `libraries.json` 里写 `access.protectRead: false`（= 回到"浏览公开、只锁管理操作"）。

### 5.3 分享怎么用

1. 管理员登录 → 顶部「☑ 选择」→ 勾选照片；
2. 要整块选，有两个入口（可叠加使用）：
   - 底部「**全选本月**」→ 把当前月份的整月照片一键选上；
   - **每个日期标题后的选择框**（在「8 月 30 日　136 张」之后）→ 点一下 = 选中 / 取消
     这一天的全部照片；若你在这一天里手动取消了几张，它会显示为**半选**。
   两个入口都按 600 张/页分页拉全，单日超过一页也不会漏选；
3. 点「生成分享链接」→ 设定标题与有效期 → 得到一条 `/s/<随机令牌>` 链接（**明文令牌只回显这一次**）；
4. 顶栏菜单里的「**分享管理**」可以查看已发出的分享并**随时撤销**。

> **链接里的地址**：默认用你打开页面时的地址（本机跑就是 `http://127.0.0.1:9000/...`）。
> 想在手机上直接转发给别人，就在 `admin.json` 里填 **`publicUrl`**（见第四章），
> 生成的链接会自动换成对外地址。这个字段**不参与任何权限判断**。

安全设计：

- **令牌不可枚举**：`secrets.token_urlsafe(32)`（256 bit），非日期、非自增 ID；库里**只存摘要**
  （`sha256`，可再加服务端 `pepper` 变 HMAC-SHA256），明文永不落盘。
- **集合在创建时固化**：写入的是"创建那一刻"的 `(rel, mov_rel)` 快照 —— 之后相册里新增 / 移动 /
  重新索引，**都不会悄悄改变已发出分享的范围**。过滤在**服务端**完成，前端隐藏只是体验。
- **判活逐请求进行、绝不缓存结论** → **撤销后下一个请求立即被拒**（页面与图片同时失效）。
- **分享 Cookie**：`sl_share`，`Path=/`（否则 `/thumb` 等请求带不上）、`HttpOnly`、`SameSite=Lax`、
  按部署情况加 `Secure`、有效期与分享过期时间对齐。
- **分享媒体不落 CDN 缓存**：分享作用域下的 `/thumb|/photo|/raw|/video` 一律返回
  `Cache-Control: private, no-store`（管理员仍保持 `public`）。

### 5.4 配置（`libraries.json` 的 `access` 段，全部可选）

```json
{
  "access": {
    "protectRead": true,
    "maxItems": 5000,
    "share": { "enabled": true, "defaultExpireDays": 0, "cookieSecure": "auto", "pepper": "" }
  }
}
```

| 字段 | 缺省 | 作用 |
| --- | --- | --- |
| `protectRead` | `true` | 只读接口默认拒绝。**仅在配了管理口令时生效** |
| `maxItems` | `5000` | 单条分享允许的最大照片数（防止一次性把整库塞进快照） |
| `share.enabled` | `true` | 是否允许创建 / 访问分享 |
| `share.defaultExpireDays` | `0` | 创建时未指定则用的默认有效天数（`0` = 不过期） |
| `share.cookieSecure` | `"auto"` | `auto` = 以 `X-Forwarded-Proto` 为准；`always` / `never` 强制 |
| `share.pepper` | `""` | 非空则令牌摘要改用 HMAC-SHA256（换 pepper 会让旧链接全部失效） |

### 5.5 放到 Cloudflare（或任何反向代理）后面时

- **必须让分享媒体绕过缓存**：给 `/thumb`、`/photo`、`/raw`、`/video` 配置 **Bypass Cache**
  （Cache Rule）。否则被 CDN 缓存的图片**可能在撤销后仍然可访问**，撤销就不算即时生效。
- 走 HTTPS 时，`share.cookieSecure: "auto"` 会依据 `X-Forwarded-Proto: https` 自动给分享
  Cookie 加 `Secure`；若你的反代不转发该头，请显式设 `"always"`。
- 分享**媒体**已由服务端强制 `private, no-store`，但**页面的 302、Cookie 下发**等仍建议
  在边缘层一并放行（不缓存带 `Set-Cookie` 的响应）。
- ✅ **本项目的 Cloudflare 部署已按上面配好，并已实测确认**：撤销后经 CF 的公网链接访问，
  页面与图片**立即**失效（等价于直连链路的行为）。

### 5.6 已知限制（验收边界，请知悉）

1. **同一台设备上先后打开两条分享链接，后一条会覆盖前一条** —— 两条链接用同一个 Cookie 名
   （`sl_share`），浏览器只保留最后一个。换一台设备 / 换一个浏览器即可同时看两条。
2. **管理员在同一浏览器里打开自己的分享链接，看到的仍是全部照片** —— 这是**设计如此**：
   身份优先级是 admin > share，同一个浏览器里已有管理会话时以管理身份为准。
   想验证"访客视角"，请用**无痕窗口 / 另一台设备**打开链接。
3. **公网 "撤销即时生效" 依赖 5.5 的缓存绕过。** 本项目的 CF 部署已实测通过；但如果你换了
   CDN 或反代，请自行确认规则真的生效 —— 直连（不经缓存）时的即时失效已被自动化测试覆盖。

## 六、功能清单

| 能力               | 说明                                                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 多图库              | 同时挂载多个目录，顶部胶囊一键切换                                                                                                                                                    |
| **持久化索引**        | 首次全量建索引存进 SQLite；**日常启动只加载索引，不再遍历解析**                                                                                                                                |
| **增量扫描**         | 按 `(大小, mtime)` 比对，只处理新增 / 变更 / 删除；后台每 300 秒自动核对一次                                                                                                                   |
| **离线保护**         | 根目录临时掉线 → 保留索引并标记「离线」，绝不误清空                                                                                                                                          |
| 秒级索引             | 启动只扫目录和文件名，不解码图片；**12969 张 ≈ 0.4 秒**                                                                                                                                 |
| 双层懒加载            | ① 日期分组按需加载 ② 图片按需加载（首屏只请求可见的约 20 张）                                                                                                                                  |
| 分页 API           | 列表按「月/日/页」下发，手机端不下载大 JSON                                                                                                                                            |
| 服务端缓存            | 缩略图 / 大图 / 转码产物全部落盘，命中约 3–9ms；并发单飞只生成一次                                                                                                                              |
| **孤儿缓存回收**       | 缓存清单 `data/cache.db` 记录每个缓存的来源；失效/残留缓存可**先预览再回收**，且**只删 `cache/` 内文件，绝不触碰源照片**。类别：`tmp_leak`（中断残留）/ `unrecorded`（清单无记录）/ `missing_source`（源已消失）/ `changed_source`（源已改动）/ **`obsolete_variant`（缩略图旧规格，见下）**                       |
| **缩略图单档 640**     | 缩略图只有**一个规格 640**：同一张照片最多一份缩略图缓存，网格密度只是 CSS 缩放、不再切换图片 URL。历史参数（`s=240/480/960`…）由服务端统一**吸附**到 640，旧书签 / 旧页面不报错也不会生成旧档；升级时可单独执行 `?cls=obsolete_variant` 回收历史旧规格缓存（**源在回收站 / 图库离线一律保留**，不靠文件名猜规格） |
| **照片墙五档密度**      | 常驻底部控制器：`−` 更密集 ｜ 当前档名 ｜ `+` 更宽松，点档名（或顶栏密度图标）打开**五档面板**。五档为 **大图 · 标准 · 密集 · 月份 · 年份**，密度与**时间浏览层级**一起变：前三档逐日分组，「月份」收起日期头、按**月**组织，「年份」再把月份分隔降级成小标签、以**年**为主层级。切换只改 CSS 列数与分组 class —— **不动 DOM、不重新请求、不改图片 URL**（缩略图仍是同一份 640），并**锚定当前分组保住浏览位置**、对可见格子做形变过渡（尊重 `prefers-reduced-motion`）；档位记在 `localStorage`（默认「标准」） |
| **回收站（删除 / 恢复）** | 删除 = **移入 `data/trash/`**（不是永久删除），默认保留 **30 天**可完整恢复；顶栏「**最近删除**」面板可看缩略图 / 删除时间 / **剩余天数**，支持单项与批量恢复，冲突默认**不覆盖**；Live Photo 图片与配对 MOV **成组**处理；服务端强制「需管理授权、只读图库禁止删除」 |
| **访问控制（默认拒绝）**   | 配了管理口令后，只读接口**默认拒绝**：除首页外壳与身份接口外一律要身份，**本机与局域网同一套规则**；按语义返回 401（未登录）/ 403（越权）/ 404（分享不存在或已撤销）；`access.protectRead:false` 可退回"浏览公开"                       |
| **免登录分享**       | 管理员手动选择、**一键全选本月**、或**按天选择**（每个日期标题后的选择框）→ 生成 `/s/<256bit 令牌>` 只读链接；链接地址可用 `admin.json → publicUrl` 换成公网域名；**授权集合在创建时固化**并在服务端过滤；令牌只存摘要、明文只回显一次；可随时撤销且**下一个请求立即失效**；分享媒体强制 `private, no-store`（不被 CDN 缓存）    |
| **管理授权（独立）**     | 口令来自 `--admin-token` / `admin.json`，服务端下发 **HttpOnly 会话 Cookie**（值≠口令）；CSRF 双重防护（自定义头 + 同源校验）；登录失败**指数退避**；口令不进 URL/storage/日志                       |
| **索引进度面板**       | 顶栏「🔍 索引进度」：首次/全量索引显示**真实进度条**（已处理/总数/当前阶段），**总数未统计出来前不显示百分比**，只显示「正在扫描图库，统计文件数量……」；增量核对显示本次检查与新增/变更/删除数；完成显示照片/视频/Live 组数；异常显示错误数与离线图库。前端**定时轮询**，不挂起请求             |
| **选择模式**         | 顶栏「☑ 选择」→ 勾选磁贴 → 底部条「移入回收站」；支持「**全选本月**」与**每个日期标题后的选择框**（整日选中 / 取消，部分选中显示"半选"）；**破坏性操作有独立二次确认**并展示影响数量/体积；灯箱内也可删除                                                                                                       |
| **30 天自动永久删除**   | 启动检查 + 每 1800 秒定时检查 + **停机补做**；只处理账本中已登记且到期的条目；删前复核路径/类型/链接/归属，**拒绝目录**（不递归删）；「永久删除 / 清空回收站」各自二次确认并写审计                                                               |
| 流式视频             | MOV/MP4/MKV 支持完整 HTTP Range（206 / Content-Range / Accept-Ranges），256KB 分块发送，**不整读、不预转码**                                                                             |
| **独立视频**         | 单独录的 `.mov/.mp4/.m4v/.mkv/.webm`（没有同名静图）也会作为条目展示，服务端用 ffmpeg 抽帧做缩略图：**多时间点候选（0.5s→20s）逐点抽帧并做「亮度 + 对比度」打分择优**，避开开场黑场 / 白屏 / 纯色卡，全部不合格时取最接近中灰的一帧兜底 —— 保证永远有封面 |
| **视频封面预热**     | 索引完成后后台低优先级预生成视频封面（**只预热当前缩略图档位 640**，与前端请求严格对齐，带 300s 时间预算），消除 iOS 上「滚到才抽帧」的空白期；缩略图加载失败会**静默重试一次**，仍失败则显示明确的视频占位图标，不留空白格 / 问号 |
| **编码识别**         | 直接解析 MP4 box / Matroska EBML 头部识别编码（**不用起 ffmpeg**，每个约 1ms）                                                                                                          |
| 编码兼容             | `h264` 原样直出；HEVC(H.265) 在 PC 端**懒转码**为 H.264；iOS 原生支持 HEVC 则不转                                                                                                       |
| Live Photo       | iOS Safari 走 Apple 原生 LivePhotosKit；其它浏览器走 H.264 动图叠加。**实况默认静音**（自动播放的前提），灯箱顶部有喇叭开关；iOS 点喇叭会切到原生 `<video>`（LPK 按设计不出声） |
| **实况视频与静图同框**    | 动图视频用 `width/height:100% + object-fit:contain` 撑满灯箱，与静图的内容框像素级重合（手机实况视频常只有 960x720，只给 `max-*` 限制会缩在静图中间）                                              |
| 现代图片格式           | 缩略图输出 **WebP**，平均仅 **5.3 KB**                                                                                                                                        |
| EXIF 方向修正        | 手机竖拍照片自动摆正                                                                                                                                                           |
| **拍摄时间取值链**      | 时间轴按**拍摄时间**排序，逐级回退：图片 `EXIF DateTimeOriginal → DateTime` → 视频取「同目录同名的配对静图」→ 视频自身 `mvhd` → 文件名时间戳 → 覆盖表 → **`IMG_数字` 编号推算** → `mtime`。老库升级后**自动重算一次**（`TS_PROBE_VERSION`），无需重建索引 |
| **编号推算兜底**       | 完全没有拍摄时间时（EXIF 被导出工具洗掉），用同目录里**有真实时间**的 `IMG_数字` 做锚点插值补一个大致时间；只在锚点之间取值、**绝不外推**，锚点不足 3 个就不猜。避免整批老照片被 `mtime` 排到「导入日」——`scan.inferTime=false` 可关闭 |
| 搜索               | 服务端全文搜索文件名，分页返回                                                                                                                                                      |
| 年份 / 月份导航        | 顶栏下方常驻 `< 2025 >` 年份切换 + 该年月份条；滚动时自动同步当前年月；点月份直接跳转                                                                                                                   |
| 月份跳转             | 底部面板一键跳到任意月份                                                                                                                                                         |
| 详情面板             | 文件名 / 时间 / 大小 / 分辨率 / 配对方式 / 路径，可下载原图                                                                                                                                |
| 安全               | 多根目录隔离，拒绝 `..` / 盘符绝对路径 / 符号链接穿越                                                                                                                                     |
| 防重复启动            | PID + 端口双重探测                                                                                                                                                         |

### 接口一览

> 配了管理口令（`protectRead`）时，下表中**除 `/api/session` 与 `/api/admin/status` 外**，
> 所有接口都要求身份：admin 全部可读，share 仅 `SHARE_GET` 白名单
> （`/api/libs`、`/api/tree`、`/api/items`、`/api/search`、`/api/item`、`/thumb`、`/photo`、`/raw`、`/video`）
> 且逐条校验授权集合，其余一律 403。

| 端点                                           | 用途                                                                               |
| -------------------------------------------- | -------------------------------------------------------------------------------- |
| `GET /api/session`                           | **统一身份接口**：`{scope: admin\|share\|anon, protectRead, shareEnabled, canManage, share?}`；前端判断身份的唯一依据 |
| `GET /s/<token>`                             | 分享落地页：校验令牌 → 下发 `sl_share` Cookie → 302 到相册（无效统一 404，不区分"已撤销"以免被探测）             |

| `POST /api/share/list`                       | 列出已发出的分享（**绝不回显令牌**）；需管理授权                                                       |
| `POST /api/share/revoke`                     | 撤销分享 `{id}` 或 `{ids:[...]}` → **下一个请求立即失效**；需管理授权                                    |
| `GET /api/libs`                              | 图库列表与统计                                                                          |

| `GET /api/item?lib=&p=`                      | 单条详情（含 Live 配对信息）                                                                |
| `GET /api/index`                             | 索引状态（行数 / 配对数 / 体积 / 各库最近核对增量）                                                   |

## 八、关键设计决策

| 决策                                     | 原因                                                                |
| -------------------------------------- | ----------------------------------------------------------------- |
| 单文件 Python 服务 + 纯静态前端                  | 交付形态是"双击运行的本地工具"，不引入构建链                                           |
| 缩略图用 **WebP** 而非 JPEG                  | 体积约为 JPEG 的 1/3，且保留 PNG 透明通道                                      |
| 分组骨架按真实数量渲染                            | 避免"空分组高度为零 → 几十个分组同时命中视口"导致一次性加载                                  |
| 骨架高度按「单元格宽 × 行数」精确计算                   | 骨架只有 24 个占位而真实一天可能几百张；高度算错会在换成真图时把滚动位置顶走上万像素                      |
| `body` 用 `min-height` 而非 `height:100%` | 写 `height:100%` 会把 body 盒子锁成一屏高，所有 `position:sticky` 子元素一出首屏就失去吸附 |
| 时间轴跳转后连续几帧重新对齐                         | 网格从骨架换成真图、图片布局是异步的，锚点会被推走，需要收尾对齐                                  |
| **删除 / 恢复后原地重建，而不是回顶部**                 | 时间轴是「滚到哪渲染到哪」的懒加载；删完一张就回顶部，顶部永远是最新的月份，用户会以为「跳到了别的月份」。重建前记住视口顶部的日期分组，重建后先渲染到它再滚回去；该日分组被删空时退到时间上紧邻的下一天 |
| Live Photo 降级**降媒体源**、不降播放器            | 实测 LivePhotosKit 换 H.264 源在 Edge 上照样能播，无需自研                       |
| 实况**默认静音**，声音做成开关                     | 「muted + playsinline」是浏览器放行自动播放的前提，默认出声等于每次都要用户点；iOS 更别无选择——LPK 源码里就把 `video.muted=true`、`volume=0`，只能换回原生 `<video>` 才有声 |
| 实况视频按**静图的框**渲染，而不是自己的原始尺寸         | 静图是 `contain` 铺满灯箱的，视频若只受 `max-width/height` 约束，比视口小的 960x720 视频就会缩在中间，出现「外面一圈静图、里面一小块在动」 |
| 索引阶段不解码图片                              | 12969 张解码需几分钟，秒级索引是体验底线                                           |
| **用 SQLite 持久化索引，而不是每次重扫**             | 只靠内存索引，每次重启都要重读全部 MOV 头；持久化后日常启动是「读索引」，新增 / 变更才重算                 |
| **派生字段带 `checked` 标记**                 | MOV 的 CID、图片的 Live 标记只在「新增或变更」时重算，未变的行永不重复解析                      |
| **只重解析受影响分组的 MOV**                     | 增量扫描精确到 `(目录, 主名)` 分组，避免为一张新图重扫整个图库                               |
| **根目录离线 ≠ 空图库**                        | 目录临时不可访问时保留索引并标记「离线」；把它当空库会瞬间清空使用者攒下的索引                           |
| **用 box / EBML 解析认编码，不启 ffmpeg**       | 每个文件约 1ms；起一次 ffmpeg 进程要几十到几百 ms，几千个视频就是分钟级                       |
| **编码探测算法带版本号**                         | 升级识别逻辑时自动作废旧缓存（`CODEC_PROBE_VERSION`），避免旧值长期污染                    |
| **缓存键包含 `lib_id`**                     | 多图库下同名文件的缩略图必须隔离，否则会串图                                            |
| 时间戳只认「被分隔符完整包住」的 10/13 位数字             | 企微的文件名是 UUID，零散数字会被误判成 2098 年                                     |
| **时间轴用拍摄时间，而不是 mtime**                    | 手机导出名是 `IMG_1644.JPEG`，既没有时间戳，`mtime` 又是「拷贝进硬盘那天」；只靠它会把 2024 年的照片排到拷贝当天 |
| **视频时间宁可取配对静图，也不信 `mvhd`**               | 实测 914 组 Live Photo 里 **37%** 的 MOV 时间戳被重新导出改写过（整段写成同一个「导出日」），静图 EXIF 才可靠   |
| **编号推算放在覆盖表之后、`mtime` 之前**                | 覆盖表是人工核过的，优先级必须高于自动推算；而 `mtime` 是最不可信的兜底，能推就一定不要用它              |
| **推算只在同目录锚点之间做插值，绝不外推**               | 编号未必是全局拍摄序（换机、重装会重编号）；只夹在已知区间内取值，宁可保守也不制造离群点               |
| **推算不碰已有真实时间的记录**                        | 判别依据是 `ts == mtime`（取值链没取到任何东西时的兜底签字）；已有 EXIF 的文件永远不会被改写            |
| **覆盖表只放服务端算不出来的部分**                     | EXIF / 配对 / mvhd / 文件名时间戳服务端自己能读，写进覆盖表只会制造两份真相                        |
| 同名 `.png` / `.jpg` 视为两个条目              | 真实数据里有 885 组同名不同扩展名的图片                                            |


## 九、仓库说明（v1.0.0 基线）

**仓库里有什么**

| 路径                                              | 说明                                       |
| ----------------------------------------------- | ---------------------------------------- |
| `server.py`                                     | 服务端（标准库 `http.server` + SQLite，无 Web 框架） |
| `index_db.py` / `cache_db.py` / `trash_db.py`   | 索引 / 缓存清单 / 回收站账本                        |
| `share_db.py`                                   | 分享账本（独立库，删掉即回滚访问控制/分享）               |
| `web/`                                          | 前端（原生 HTML + CSS + JS，无构建步骤）             |
| `tests/`                                        | 自动化测试（Python 专项 + Playwright 端到端）        |
| `tools/photo_time_repair.py`                    | 拍摄时间核查 / 推算脚本（见下方「照片时间不准怎么办」）            |
| `libraries.example.json` / `admin.example.json` | 配置模板                                     |
| `一键启动.bat` / `一键结束.bat`                         | Windows 启停脚本                             |
| `*.md`                                          | 设计文档与验收报告                                |

**仓库里刻意没有什么**

| 路径                 | 原因                           |
| ------------------ | ---------------------------- |
| `data/`            | 索引库、缓存清单、回收站账本与回收站里的**真实文件** |
| `cache/` `logs/`   | 缩略图 / 转码产物 / 访问日志            |
| `tmp/`             | 测试用的临时工作树与运行输出               |
| `libraries.json`   | 含**本机绝对路径与私有目录名**            |
| `admin.json`       | 含**管理口令**                    |
| `tests/e2e/shots/` | 端到端测试截图（**含真实照片画面**）         |
| `tools/out/`       | 时间核查脚本的产物（**含本机照片路径与私有目录名**）  |

以上全部写在 **`.gitignore`** 里，用 `*.example.json` 提供模板。

**首次克隆后怎么起步**

```bash
python server.py --init        # 生成 libraries.json 模板
# 把里面的 root 改成你的照片目录
python server.py --lan         # 启动（Windows 下也可直接双击 一键启动.bat）
```

**控制台刷 `ConnectionResetError: [WinError 10054]` 是什么**

客户端提前断开（关标签页、灯箱里换图、视频/封面预加载被取消）时，复用连接上的
下一次读请求行就会撞上它。这是 HTTP 的日常、不是故障，服务端已用
`ThreadingHTTPServer.handle_error` 静默掉这类连接级异常（只留 `debug` 日志），
其余异常照常打印堆栈。

**照片时间不准怎么办**（时间轴排在了「导入日」而不是拍摄日）

时间轴默认读 **EXIF 拍摄时间**；排错的那些文件，基本是真的没有 EXIF
（截图、聊天软件保存的图、被导出工具改写过元数据的文件）。

**这种情况现在服务端会自己处理**：取值链在退回 `mtime` 之前，会拿同一个目录里
**有真实时间**的 `IMG_数字` 当锚点做编号插值，给它们补一个大致时间
（`infer_library_ts()`，见 `server.py`）。所以**新加图库不需要任何手工步骤** ——
索引完就排好了；推算只在扫描时跑一次，之后幂等不再改动。想关掉：`libraries.json`
的 `scan.inferTime: false`。

`tools/photo_time_repair.py` 保留为**核查 / 微调**手段（服务端跑的是同一套算法）：

```bash
python tools/photo_time_repair.py report      # 只读核查：覆盖率 + 单调性 + 逐文件明细 CSV
python tools/photo_time_repair.py cv          # 留一法交叉验证，看这套推算到底准不准
python tools/photo_time_repair.py overrides   # 生成覆盖表（人工复核后用来压过自动推算）
```

覆盖表默认写到 `tools/out/ts_overrides.json`，服务端启动时自动加载（也认
`data/ts_overrides.json`，或用 `--overrides 路径` 指定），**优先级高于自动推算**。
另有 `apply` / `restore` 两个模式会**回写文件的 mtime**（先备份、可一键还原）——
属于改原文件，日常不建议用，因为升级取值链本身并不需要动原文件。

> 注意：覆盖表按**相对路径**记录，跨图库共用同一个文件时，不同库里同名的相对路径
> 会互相命中。只有带子目录的相对路径才足够精确（现在生成的都是这种）。
> 排查时间问题时可以先看 `logs/server.log` 里的
> `时间推算：<lib> 按 IMG 编号找回 N 个文件的时间（锚点 M 个）`。

## 十、许可与免责

- **照片安全**：程序默认**只读**图库目录；只有显式配置 `deletion_enabled` 且完成管理授权后，
    
  才会执行"移入回收站"（**移动，非删除**）。即便如此，**任何删除类操作请自行先行备份**。
- **网络风险**：`--lan` 为**明文 HTTP**，链路上可被嗅探。
    
  **配了管理口令时**，访问保护对浏览同样生效（本机与局域网一致），但明文链路仍可能泄露
  会话 Cookie / 分享令牌；接入公司网络或公网前，请务必套一层 HTTPS 反代，
  并参考「5.5 放到 Cloudflare 后面时」配置缓存绕过。
    
  **没配口令时**，浏览完全公开，局域网内任何设备都能看全部照片（含原图）——
  此时管理口令无从谈起，请自行在网络层做隔离。

## 十一、从 GitHub 克隆使用

```bash
git clone https://github.com/MasonWest/SeekLive.git
cd SeekLive

# 依赖（只有两个：HEIC 支持 + WebP 缩略图）
pip install Pillow pillow-heif

# 生成图库配置，再把 root 改成你的照片目录
python server.py --init

# 启动（双击 一键启动.bat 等价于此）
python server.py --lan
```

浏览器打开 `http://127.0.0.1:9000/`。**不配口令时浏览完全公开**；需要访问保护 + 删除功能时，
另建一份 `admin.json`（模板见 `admin.example.json`）或加参数 `--admin-token "<你的口令>"` ——
此时浏览同样需要口令或分享链接，详见「五、访问控制与免登录分享」。

**环境要求**：Python 3.8+（Windows / macOS / Linux 均可），无需数据库、无需 Docker、
无第三方 Web 框架 —— 服务端只用标准库 `http.server`。

### ffmpeg（强烈建议安装，否则视频只能是黑封面）

ffmpeg 负责两件事，缺了它这两件事都做不了：

1. **视频封面抽帧** —— 独立视频的缩略图全靠它；没有它 `/thumb` 只能返回 500，
   格子里就是一个黑块（Live Photo 因为用配对静图当封面，不受影响）。
2. **HEVC(H.265) → H.264 转码** —— iPhone 的 Live Photo 视频与部分录像都是 HEVC，
   iOS/Safari 能原生解码，**桌面 Chrome/Edge/Firefox 不能**。此时点 LIVE 只会得到
   一个黑掉的小窗，必须靠服务端转码。

装到哪里都行，按以下顺序自动探测（找到即用）：

```
环境变量 FFMPEG_BIN → 项目根目录的 ffmpeg.exe → 若干本机常见路径 → PATH
```

最省事的做法：把 `ffmpeg.exe` 直接丢进项目根目录。服务启动时探测一次；若启动时
还没有、之后才放进来，**不用重启** —— 首次用到时会自动补探并接上（间隔 30 秒）。
`ffmpeg.exe` 已在 `.gitignore` 中，不会进版本库。

可随时访问 `/api/stats` 看 `"ffmpeg": true/false` 确认是否被识别到。
